## 闭环结果

容器内运行实际 ArduCopter、MAVROS 和项目飞行节点；飞机状态来自
ArduCopter 动力学积分，通过 MAVROS 送回控制器。测试正常解锁，未强制解锁。

| 场景 | 结果与判据 |
| --- | --- |
| 地面解锁后 CH5 触发自动起飞，保持低油门杆 | 通过；相对升高约 1.001 m，完成后继续悬停 |
| 悬停后关闭 CH5 | 通过；实际飞控模式确认切至 ALT_HOLD |
| 第二次起飞中途关闭 CH5 | 通过；爬升约 0.25 m 后取消，实际飞控确认 ALT_HOLD |
| 第三次起飞中断里程计输入 | 通过；实际飞控确认 ALT_HOLD |

正常起飞后最后 2 秒的最大高度误差约 **0.0013 m**，最大水平位移约
**0.0154 m**。这是该次理想仿真中的观测值，不代表真机精度。
各轮使用 LAND 实际落地，确认地面状态并上锁后才开始下一轮。
详细结果见运行目录的 `result.json`、`telemetry.json` 和各进程日志。

## 测试中发现并修复的问题

原实现要求 IMU 和里程计时间戳不能比当前 ROS 时间超前。
实际 MAVROS 时间同步后仍观察到毫秒级超前；一次爬升到约 0.5 m 时，
这触发了数据无效判断和 ALT_HOLD 接管，未完成自动起飞。

新增 `sensor_future_tolerance: 0.02`，允许最多 20 ms 超前；
原有 0.1 秒旧数据超时保持有效，明显超前的数据仍拒绝。
修复后完成上述全部闭环场景。

## 复现与范围

在项目根目录执行：

```bash
./scripts/test_auto_takeoff_sitl.sh
```

环境和输出文件说明见 [SITL 说明](../docker/arducopter-sitl/README.md)。
测试容器不连接外部网络、不挂载串口、不访问真机。

使用 ArduPilot 内置四旋翼模型，其默认质量 3 kg、参考悬停输出 0.39。
仅测试进程将项目 `hover_percentage` 覆盖为 0.39；真机质量/推力标定
与 `params/hiarm.params` 未修改。没有复现完整真机参数、动捕/EKF链路、
变形机构、地效及实际通信延迟，因此本结果验证自动起飞与接管逻辑，
仍需拆桨检查和受控真机试验。

原 `real-robot` 未提交工作保留在 `stash@{0}`。本次测试设施、修复与报告
提交到自动起飞分支；该分支尚未推送。
