# 栖停与复飞

`flygripper_planner/params/real_perching.yaml` 保留两个接近航点，最后一次闭爪完成后，
由飞行 FSM 接管动力、开爪和后退。仅此配置启用该流程，普通抓瓶任务不启用。

在已有飞行、定位和执行器节点运行时，选择任务配置：

```bash
roslaunch flygripper_planner real.launch use_sim:=false \
  task_config:="$(rospack find flygripper_planner)/params/real_perching.yaml"
```

CH5 进入已验证的 GUIDED_NOGPS 控制，CH6 的新触发沿启动航点任务。执行器需要
`teleop_mode: 2`。当前舵机反馈不可信，YAML 显式使用 `morph_use_feedback: false`，开合只等待
命令执行时间，不宣称实际到位；必须通过下列减载试验后才允许零推力。

执行顺序：

1. 到达第一航点并开爪。在最后抓取航段开始前，记录低速飞行时最后发布的归一化推力。
2. 接近第二航点并发出闭爪命令，等待 0.9 s（可配置为反馈模式）。速度不超过 0.1 m/s、
   角速度不超过 0.3 rad/s 持续 0.3 s 后，先冻结位置/航向作为承重测试基准。
3. 3 s 内平滑减小推力命令至记录值的 15%，保持低推力 1 s，再用 1 s 平滑降至零。
   该比例是推力命令比例，不是已标定的升力比例。全过程及零推力期间检查：掉高不超过
   2 cm、下坠速度不超过 0.08 m/s、世界系垂直加速度不低于 -1.5 m/s²、位置偏移不超过
   5 cm，并要求 IMU/EKF 测量年龄和回调年龄都不超过 80 ms。这些是待实测的初始参数。
4. 若承重试验异常，同一控制周期恢复记录推力，保持开合命令不变，取消栖停，锁定测试前
   高度/航向继续有动力悬停，并在终端输出原因；不会再等待满 5 s 或继续开爪/复飞。
5. 减载试验通过后，持续发布零推力 5 s。保持解锁，不调用解锁服务。随后恢复记录的推力，
   夹爪保持闭合，等待 1 s 建立动力。
6. 发送开爪命令，同时启用高度和航向反馈，输出不低于记录的推力。接触期间不使用
   外力补偿，不累计角速度积分；开爪命令等待结束后重新初始化自适应估计。
7. 当前等待开爪命令 1 s 后，以栖停时的航向为基准，保持高度和航向，用 2 s 五次曲线后退 0.5 m。
   记录的推力下限在 2 s 内平滑过渡至正常高度控制。位置误差不超过 3 cm、低速且航向误差
   小于 0.1 rad，持续 0.3 s 后完成，保持后退终点。

所有时长和距离位于 YAML 的 `perching` 部分。5 s 从开始发布零推力起按单调时钟计算，
不是确认转速为零后计时。1 s 为建立动力的等待时间，不代表 ESC 转速已被反馈确认。
`/flygripper/perching_command` 使用任务 ID 关联 PREPARE/START/CANCEL，重复 START 不重启计时；
`/flygripper/perching_status` 发布阶段、记录推力、输出推力和结束原因。
最终接近及闭爪等待期间，规划器持续检查同一任务的 PREPARED 状态、RC 和飞行状态；
只有飞行节点确认采样并发布了本次接近轨迹后才允许按到点条件闭爪。状态过期、任务取消、
退出轨迹模式或轨迹被替换时，规划器取消任务，不继续发送闭爪命令。轨迹按时结束后的
正常悬停可继续等待到点；状态确认只反映机载控制发布，不代表飞控或夹爪的实际响应。

仅支持当前 `command_mode: 0` 姿态/推力接口，并沿用 GUIDED 进入时对 `GUID_OPTIONS` bit 3
的验证，使 thrust=0 表示零推力而非下降率。RC 退出、飞控退模/上锁、输入过期、夹爪反馈
丢失或任务超时会中止流程；不会自行重新解锁或在故障时自动开爪。停动力/建立动力期间
如果位置变化超过 0.10 m、速度超过 0.3 m/s 或航向变化超过 0.2 rad，也会中止并交回飞控。

没有减载测试期间的位移/速度，正常悬停本身不能证明抓牢。软件试验通过仍不是直接测得
承重，不能排除低推力升力、定位冻结、反馈延迟或后续滑脱。正常悬停下冻结的定位流应先
通过故障注入排查；运动/加速度与实际推力的对应关系必须另行确认。闭爪位置或过载也不能
证明支撑物已经可靠承重。独立承重传感器、自锁结构和防坠系留能提供软件之外的保障。
ROS 测试仅验证消息与状态机时序，不模拟
夹持力、电机加速、飞控落地检测或复飞动力学；若 FCU 在栖停中自行上锁，该次任务中止。

验证：`rostest flygripper_flight perching.test` 使用真实规划器/飞行节点与隔离传感器、执行器及
MAVROS mock，覆盖 5 s 输出、恢复/开爪顺序、非零航向后退、任务重放和故障中止。

CH6 退出边沿会在 RC 历史中锁存，低/高两帧同批处理也会取消任务。普通轨迹退出后进入
GUIDED/HOVER；栖停活动阶段退出会取消任务、恢复记录推力并请求 ALT_HOLD。再次进入需新的
有效开关触发，不能用同一批 RC 的高电平自动恢复。
栖停完成或承重测试失败后也返回 GUIDED/HOVER；新的 CH6 触发会丢弃旧轨迹，并对首条新轨迹
检查位置、速度和航向连续性。
最终接近期间收到 CANCEL 或 PREPARED 超时，也会撤销当前及待执行轨迹，锁定当前测量位置和
航向作为悬停目标，并要求新的 CH6 触发。重复的旧任务 CANCEL 不影响后续轨迹会话。
RC 缺少必需通道或通道值越界时，不刷新最后有效通道和接收时间；同批后续正常帧不能覆盖该
故障。活动栖停会中止并请求飞控接管；减载或零推力阶段会先恢复记录推力，不继续减载、
零推力或开爪流程。

若栖停减载期间 FCU 状态过期，已有验证会话允许短时使用缓存的水平姿态/推力桥接接管请求，
而不是保留最后一条零推力。此恢复窗口为 `recovery_duration` 限制在 0.5–2 s；窗口结束后若
输入仍不健康则停止发送，不无限维持盲飞指令。新收到的退模或上锁状态立即优先，不自动解锁。
`rostest flygripper_flight perching_ch6_exit.test` 验证该路径及切模延迟/拒绝/无确认。

`scripts/sitl/test_perching_exit.py --case airborne|ground|heartbeat --output <目录>` 可在隔离的
ArduCopter SITL + MAVROS 环境运行。ground/heartbeat 使用模拟地面作为承重夹具，不模拟夹爪；
airborne 用飞控原生起飞建立约 2 m 悬停，再交给机载控制器。stock quad 的悬停推力从 FCU
ATTITUDE_TARGET 实测，外环采用显式模型适配增益（k_pos=1,1,2；k_vel=2,2,3），L1 保持开启。
这些只覆盖仿真 ROS 参数，真机 YAML 不变。三种场景均使用实际模拟动力学/测量状态，
不复制控制参考作为位置。地面场景中 FCU 可能保持 LANDED 和怠速，不代表已验证空中升力重建。
