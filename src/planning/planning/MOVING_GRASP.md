# 移动小车抓取

运行 `./scripts/grasp_car.sh` 或 `roslaunch planning grasping.launch` 启动移动小车抓取规划器；飞行、动捕、EKF 和舵机节点由 `./scripts/run.sh` 等入口单独启动。`scripts/plan.sh` 启动的是另一条规划路径。

要查找 `planning.launch` 各参数的完整默认值、单位、适用阶段和调节影响，请看 **[小车抓取规划参数参考](PARAMETERS.md)**；本页说明任务流程、证据边界和调参顺序。文中默认值来自当前工作区，板端可能运行不同的构建或配置。

规划器使用以下话题：

- `/vrpn_client_node/HIARM_car/pose`：小车动捕位姿，类型为 `nav_msgs/Odometry`。
- `/vrpn_client_node/HIARM_car/twist`：小车动捕速度，类型为 `geometry_msgs/TwistStamped`。
- `/ekf/ekf_odom`：无人机的里程计数据。
- `/flygripper/flight_trajectory_status`：飞行节点发布的轨迹执行状态。

上述数据需要对应同一个经过校准的世界坐标系。小车线速度取自 twist 消息的 `twist.linear.x/y/z`，不再通过位置差分计算。小车 yaw 角速度仍通过连续两帧位姿的姿态变化估算；当前不将 VRPN 驱动发布的 `twist.angular` 字段视为角速度。可在 `planning.launch` 中通过 `target_twist_topic` 修改速度话题。

`grasping.launch` 选择小车抓取模式，`planning.launch` 在该模式下使用 `twist` 作为速度来源。速度话题丢失时，不会自动退回位置差分。通用的 `planning.launch` 为兼容已有仿真入口，默认使用原有的 `pose_difference` 来源；速度来源在 `planning.launch` 中配置。

小车世界系 XYZ 平移速度在用于目标预测、航向、闭爪及异常退出判断之前，经过一阶低通滤波。`target_velocity_cutoff_hz` 为截止频率，单位 **Hz**，默认 **3.0**；设为 **0** 关闭滤波，负数或非有限值会告警并回退到 3 Hz。频率越低越平滑，但启动、停车和转向时的响应也越慢。3 Hz 对应时间常数约 0.053 s，是待实飞验证的初始设置。

滤波只在接收新的有效速度样本时更新，系数为 `1-exp(-2*pi*target_velocity_cutoff_hz*dt)`，`dt` 使用相邻测量的 header 时间差，不使用规划周期或消息集中到达时的回调间隔。首帧直接使用实测速度；测量间隔或接收间隔超过 `target_twist_timeout`、坐标系改变时丢弃旧滤波状态。重复和倒退时间戳不更新速度或新鲜度。数据持续到来时，重新触发任务保留滤波状态；兼容的 `pose_difference` 输入也经过相同滤波。

目标位置预测、闭爪相对速度与航向判定，以及闭爪、抬升期间的异常退出判断都使用滤波后的速度。滤波可能延迟对突然启动、停车或转向及相对速度异常的判断，短时速度突变也可能被衰减；不改变数据超时条件。`/drone0/replanState` 的 `target.twist.twist.linear` 记录用于运动预测的滤波后抓取点速度，原始小车速度仍从输入 twist 话题读取。

启动前在 `src/planning/planning/launch/planning.launch` 中修改 `target_velocity_cutoff_hz`；例如设置为 `0` 可关闭滤波。修改后重启规划器，不支持运行中 `rosparam set` 热更新，也不再通过 `grasping.launch` 命令行传入这些参数。

`pos_dx/pos_dy/pos_dz` 表示期望的无人机参考点相对于小车动捕刚体原点的偏移，单位为米，在小车刚体坐标系中定义。默认偏移仍为 `(0, 0, 0.09)` 米。

## 抓取流程和反馈假设

该流程假设每次闭爪命令都能执行，夹爪闭合耗时 0.85 秒。代码不使用舵机反馈或接触测量来确认物体是否被夹住。

1. **接近目标**：小车模式预测抓取点，并以滤波后的水平运动方向反向偏移 0.25 m，得到同高度的预接近点；预测序列用于路径搜索、跟踪代价和接近轨迹终点。终点速度使用预测抓取点速度（再加 `grasp_vx/vy/vz`，超出 `vmax` 时优化器会裁剪），yaw 使用滤波运动方向的预测值。轨迹终点的 yaw 受角速度与角加速度限制，不保证能够到达目标角度。无人机里程计位置与当前预测抓取点的三维距离首次不超过 0.30 m 后，锁定抓取点规划模式，直到下次 `/triger`；不要求先到达预接近点或对齐 yaw。锁定后即使距离再次增大，也优先使用受限的五次多项式跟随真实预测抓取点；连接不可行时可尝试以抓取点为目标的优化轨迹，不再生成预接近目标。如果还没有发布过本次锁定后的抓取点轨迹，而新轨迹也不可行，则尝试制动并中止，不能把旧预接近轨迹当作抓取点轨迹继续沿用。预接近时目标距无人机超过 2 m，轨迹终点仍采用预接近路径末端的阶段性点。
2. **检查闭爪条件**：默认要求位置误差不超过 0.02 米、相对速度不超过 0.10 米/秒、实际 yaw 误差不超过 10°，航向方向就绪，并连续满足 0.15 秒；目标数据和无人机里程计也需要保持新鲜。飞行节点必须报告飞控状态新鲜、已解锁、处于 GUIDED_NOGPS，并正在执行本次任务已发布的轨迹。参数 `velocity_heading=false` 时跳过方向就绪确认，但其他条件仍生效。
3. **闭爪并继续跟随**：发布首次闭爪命令后，使用单调时钟开始计时，并继续跟随移动抓取点至少 0.85 秒。重复发布闭爪命令不会重置计时。原先仅凭距离就提前闭爪的路径已移除。
4. **跟随抬升**：水平跟随小车的同时，在 2 秒内平滑增加 0.20 米的垂直偏移。偏移曲线在起点和终点的速度、加速度均为零；重新规划的连接轨迹与上一条参考轨迹的位置、速度和加速度衔接。
5. **减速悬停**：抬升计时结束后，使用五次多项式轨迹减速至固定点悬停，并保持减速轨迹起点的位置、速度和加速度连续。该阶段结束当前任务，不规划后续搬运路线。

飞行节点的状态仅表示本轮成功采样轨迹并发布了控制输出，不能证明飞控已收到命令或无人机实际跟随。规划器核对轨迹 ID 和起始时间，并检查状态时间戳和接收间隔（默认不超过 0.20 秒）。每次任务先确认目标位姿、速度和里程计有效，并等待飞行节点处于轨迹模式，再从新鲜里程计生成短时匀速初始轨迹，确认飞行节点实际采样并发布该任务的轨迹后，才开始接近规划和抓取时序。无人机当前速度超过规划器 `vmax` 时，初始轨迹不会发布，需先降低速度。接近、闭爪或抬升期间状态失效或超时会锁定异常，停止抓取时序并尝试制动；状态恢复不会自动恢复任务。

后续任何阶段再次收到 `/triger`，立即发布 `MODE_POSITION` 张爪命令（默认位置 0 rad），等待至少 0.85 秒，并等待可能正在执行的制动轨迹结束，再建立新任务初始轨迹。原任务处于保持或中止状态时，不再在张爪等待期间重复发送旧保持点；一旦飞行节点离开轨迹模式，原任务的保持点不会在重入时自动恢复。飞行节点每次从 GUIDED 进入轨迹模式时清除旧轨迹；首条新轨迹与当前无人机及参考的位置相差超过 0.15 m、与实际速度相差超过 0.30 m/s，或多项式航向与实际或参考航向相差超过 30° 时会被拒绝。多次触发会重新开始张爪计时。张开是否完成依赖计时假设，没有夹爪位置反馈确认。飞控退出轨迹控制时，制动命令也可能无法执行。舵机节点需使用 `teleop_mode=2` 才会消费规划器发布的位置命令。

闭爪已发送后的制动、保持或异常保持阶段，规划器仍会重复发布闭爪位置命令；退出轨迹模式本身不会自动发布张爪命令。重新触发才开始张爪时序；规划器发布命令、舵机写入与 ACK、实时位置反馈、物体是否被夹住，需要分别确认。

## 数据新鲜度与异常退出

小车位姿和无人机里程计的新鲜度同时检查消息时间戳和单调时钟记录的接收间隔。twist 新鲜度默认检查：

- 接收间隔不超过 `target_twist_timeout=0.20` 秒；
- header 时间戳非零且严格递增；
- 位姿和速度消息的接收时间差不超过 `target_pose_twist_max_skew=0.15` 秒。

当 VRPN 驱动使用 `use_server_time=true` 时，位姿和 twist header 共用同一个启动时偏移估计：驱动以已订阅的位姿消息为样本，取前 600 条服务器时间与本机接收时间之差的平均值，之后从两种消息的服务器时间中减去该值。校准完成前不发布 twist；若没有位姿订阅者或位姿消息，校准不会完成。该偏移在进程内由所有 tracker 共用，启动后不会自动更新。

这个估计包含校准期间的传输及处理延迟，并不等于经过独立同步验证的真实时钟偏差。因此，即使两种 header 使用同一校正，固定延迟仍可能被掩盖，时钟漂移也可能影响结果。默认 `target_twist_check_header_age=false`；若要设为 `true`，应先验证当前驱动输出的时间戳与本机时钟之间的误差和延迟满足应用要求，并注意该检查不能证明绝对延迟足够小。部署旧版驱动时 twist 仍使用未经该校正的服务器时间。

位姿和速度的接收时间差只是测量时间差的近似值，并不等于时钟同步。预测器使用恒定转率模型，将最新速度近似旋转回位姿接收时刻。当前驱动可能不填写 `frame_id`，所以规划器接受空 frame ID；实际坐标系是否对齐仍需验证。

跟踪开始后，目标或里程计超过 0.20 秒未更新、闭爪或抬升时误差过大、预测无效，或无法生成符合限制的跟随轨迹时，代码会锁定异常状态，尝试受控减速并保持。闭爪阶段默认位置误差上限为 0.20 米，抬升阶段单独使用 `grasp_lift_abort_distance`，默认 0.10 米；两者都是三维位置误差。相对速度上限为 0.50 米/秒，yaw 误差上限为 45°；抬升时速度误差只检查水平分量，因为垂直运动是预期动作。0.10 米只是未经实飞验证的初始值；它限制抬升期间的偏差，但计时结束时仍不能证明物体已离开小车。

若无法生成可行的减速多项式，代码会记录错误并请求固定位置保持。异常时不会自动发送释放命令，因为物体可能已经被夹住。需要新的 `/triger` 才能重新开始；重新触发会先张开夹爪。飞行模式切换仍由飞控现有的模式和输入保护处理。规划器使用自由空间模型，不具备障碍物避让能力。

## 航向

在真机小车规划流程中，`velocity_heading=true` 的优先级高于旧的 `hold_yaw` 设置。目标 yaw 为 `atan2(car_origin_vy, car_origin_vx)` 加上 `grasp_heading_offset`（默认 0）：它使用小车动捕刚体原点的世界系速度，而不是无人机接近目标的方向，也不是存在偏移时抓取点的切向速度。

航向预测从连续的滤波水平速度方向估计角速度，而不使用车身的 yaw 角速度。运动方向已经确认、3 Hz 滤波速度及方向滤波结果均达到 0.08 米/秒，且连续样本间隔不超过 0.20 秒时，才计算速度方向的角速度；使用与方向滤波相同的 Hz 参数平滑，并限制在 ±0.60 rad/s。低速、方向不一致或采样间隔过长时角速度置零，保持方向本身仍按低速确认规则处理。若限制允许，三次航向轨迹到达预测终点方向；否则在角加速度限制内继续朝目标转动。位置轨迹预测仍使用小车车身姿态的恒定转率模型，这一模型依赖车身转动与速度变化的关系。

默认 yaw 角速度上限为 0.60 rad/s，角加速度上限为 1.20 rad/s²。航向计算先使用 `target_velocity_cutoff_hz` 的滤波结果，再使用 `grasp_yaw_velocity_filter_hz` 的方向滤波；两级串联。`planning.launch` 将方向滤波设为 1.0 Hz，系数为 `1-exp(-2*pi*Hz*dt)`；仅接受大于 0 的有限值。参数缺失或无效时，代码回退到 0.6366197723675814 Hz，等效于旧版 0.25 秒时间常数。旧参数 `grasp_yaw_velocity_filter_tau` 不再读取，部署时需同步更新启动文件并重启规划器。闭爪相对速度门限使用 3 Hz 滤波后的速度。

速度方向和静止都需要持续确认。3 Hz 滤波速度及其方向滤波结果同时低于 0.05 米/秒并持续 0.25 秒，才确认静止并允许使用保持航向；速度达到 0.05 而低于 0.08 米/秒时，方向需稳定 0.50 秒；达到或超过 0.08 米/秒时需稳定 0.25 秒。3 Hz 滤波速度方向与方向滤波结果相差超过 45° 时禁止闭爪。该条件不能阻止所有较小方向突变时沿滞后的滤波方向闭爪：例如速度方向在一个采样间隔内变化 40°，仍可能在实际方向未对齐时通过闭爪门限；本次角速度修改没有消除此缺口。只有新的、时间戳递增的 twist 样本推进确认计时。滤波可能延迟检测实际启动和方向变化。
静止时保持上一次确认的运动方向（包括重新触发）；若任务尚无确认过的运动方向，使用首次有效数据中无人机指向抓取点的水平角度，水平间距不超过 1 mm 时回退当前无人机 yaw。重新触发时，以及方向更新的样本接收时间间隔超过 0.20 s 时，保留已有 yaw 和上次可靠方向，但清除运动及静止就绪状态、方向滤波历史和确认计时；后续新鲜样本必须重新持续确认运动方向或静止后才允许该项闭爪条件达标。方向稳定后使用经过两级滤波的运动方向及预测角速度更新预接近点。滤波和外推可能滞后或预测错误，转弯时预接近点的几何速度不一定等于指定的抓取点终点速度。在 0.05～0.08 米/秒的过渡区间，闭爪可能等待方向确认或速度稳定。角度沿最短方向展开。设置 `velocity_heading=false` 时，真机规划器保持触发时的 yaw；旧的 fake/debug 路径独立处理。

`/drone0/planning/pregrasp_target` 是 `nav_msgs/Odometry`，表示接近预测时域末端的预接近候选：header 是预测未来时刻，pose 为目标位置和 yaw，twist 是预测抓取点速度和航向角速度。它在优化成功前发布，不能证明轨迹已生成、被飞行节点采样或实际执行；超过 2 m 时优化终点可能是阶段性路径末端。锁定抓取点模式后不再发布新的预接近目标。`/drone0/planning/grasp_point_mode` 是锁存的 `std_msgs/Bool`：首次进入 0.30 m 后为 `true`，新的抓取触发后变回 `false`；它表示规划器的模式选择，不表示抓取点轨迹已成功发布或执行。`/drone0/planning/grasp_alignment` 的 `Vector3Stamped` 分量依次是预测抓取点到实际里程计的三维距离（m）、三维相对速度（m/s）、实际 yaw 误差绝对值（rad），供诊断使用。`pregrasp_circle` 和 `pregrasp_direction` 是围绕预测时域末端的圆和直径 `nav_msgs/Path`，不是无人机轨迹；切换后不再刷新，显示工具可能保留旧图形。以上可视化和诊断不代表物理抓取。默认录包脚本订阅上述三个状态话题。

## 测试参数和调节顺序

下表中的值是当前工作区启动文件的默认值，不代表实际板端已经加载这些值；0.85 秒闭爪时间是计时假设，航向与物体实际方向的匹配也需要现场验证。建议先标定抓取点和夹爪，再检查闭爪门限、航向，最后结合跟随效果调整运动限制；每次尽量只改一项。

### 1. 抓取点与夹爪

| 参数 | 默认值 | 测试时观察什么 |
|---|---:|---|
| `grasp_height` / `pos_dz` | 0.09 m | 闭爪时夹爪相对物体是否过高或过低。`grasp_height` 设置内部参数 `pos_dz`，即抓取点相对小车动捕刚体原点的 Z 偏移。 |
| `pos_dx`、`pos_dy` | 均为 0 m | 夹爪是否始终偏向物体一侧。偏移定义在小车刚体坐标系中，会随车体姿态旋转；标定时也要考虑无人机里程计参考点与夹爪安装位置的偏移。 |
| `grasp_position` | -12.7 rad | 闭爪位置命令是否适合物体和机构；该值直接发送给舵机控制链。 |
| `grasp_open_position` | 0 rad | 重新触发时，张爪位置命令是否对应足够的开口。 |
| `grasp_close_duration` | 0.85 s | 首次闭爪命令发出后，继续跟随多长时间再开始抬升。 |
| `grasp_open_duration` | 0.85 s | 重新触发后假定张开所需的等待时间；如有可靠实测可调整。 |

`grasp_position=-12.7 rad` 约为 -727.7°；之前讨论的 -700° 约为 -12.217 rad，两者相差约 27.7°。这只是命令单位换算，不表示舵机实际到达该位置，也不能仅凭差值判断哪个更合适。当前没有有效夹爪反馈，张开、闭合与抓住物体都需要通过实际动作观察确认。

这些参数均在 `launch/planning.launch` 中修改。

### 2. 闭爪门限

| 参数 | 默认值 | 调节影响 |
|---|---:|---|
| `grasp_start_dis` | 0.02 m | 三维位置误差门限。调小要求对得更准，但可能长时间无法闭爪；调大可能在偏差更大时闭爪。 |
| `grasp_max_relative_speed` | 0.10 m/s | 闭爪前三维相对速度门限。调小要求无人机与抓取点速度更接近，但可能更难满足。 |
| `grasp_max_yaw_error` | 0.174533 rad，约 10° | 实际 yaw 与规划目标 yaw 的允许误差。调小更严格，但可能延长等待。 |
| `grasp_gate_duration` | 0.15 s | 门限连续满足的时间。调大可减少短暂达标后闭爪的机会，但会增加等待。 |

这四项均在 `launch/planning.launch` 中修改。测试时先记录位置、相对速度和 yaw 误差，判断具体是哪项条件未满足，再决定是否调整；飞控轨迹状态和航向方向确认也必须有效。

### 3. 小车速度方向与航向

| 参数 | 默认值 | 测试时观察什么 |
|---|---:|---|
| `grasp_yaw_speed_low` | 0.05 m/s | 低速静止判断门限；应结合小车静止时的动捕速度噪声。 |
| `grasp_yaw_speed_high` | 0.08 m/s | 区分较低和较高速度方向确认的门限；速度偏低时方向确认更慢，方向角速度前馈也会关闭。 |
| `grasp_yaw_velocity_filter_hz` | 1.0 Hz | 截止频率降低通常使方向更平稳但响应更滞后；增大则响应更快，也更容易受噪声影响。缺失或无效时回退到 0.6366197723675814 Hz。 |
| `grasp_yaw_direction_dwell` | 0.25 s | 静止或运动方向的确认时间；滤波速度处于 0.05～0.08 m/s 时，运动方向确认使用两倍时间，默认 0.50 s。 |
| `grasp_yaw_rate_max` | 0.60 rad/s，约 34.4°/s | 规划 yaw 角速度上限。转向跟不上时，需结合实际 yaw 响应判断。 |
| `grasp_yaw_acc_max` | 1.20 rad/s² | 规划 yaw 角加速度上限，影响转向的快慢和变化平滑程度。 |

这些参数均在 `launch/planning.launch` 中修改。

航向闭爪判断仍有上文所述的方向突变缺口：当前条件可能使用滞后的滤波方向，单靠调整滤波参数不能保证消除该问题。应先处理这一逻辑，再将动态转向抓取作为验证目标。

### 4. 跟随与抬升

| 参数 | 默认值 | 测试时观察什么 |
|---|---:|---|
| `vmax` | 0.70 m/s | 跟随轨迹的速度限制。小车加速或速度增大后若无法生成轨迹，应检查是否受三维运动及该限制共同影响。 |
| `amax` | 0.70 m/s² | 跟随轨迹的加速度限制。过小可能难以跟上变化；增大则产生更激进的参考运动。 |
| `grasp_lift_abort_distance` | 0.10 m | 抬升阶段三维位置跟踪误差上限。频繁触发时先分析实际跟踪误差及原因，再决定是否调整。 |
| `post_grasp_lift` | 0.20 m | 目标抬升高度；达到计时结束并不证明物体被抓住或实际抬升达到目标。 |
| `grasp_lift_duration` | 2.0 s | 平滑增加抬升偏移所需的时间；期间继续水平跟随小车。 |

这些参数均在 `launch/planning.launch` 中修改。直接跟随连接轨迹会检查速度和加速度限制；接近阶段优化器仍使用基于惩罚项的约束，近距离跟随生成失败时可能回退以抓取点为目标的优化器；因此不能将这些值当成所有阶段实际飞行速度和加速度的绝对上限。`vmax` 是三维速度参考参数，不是物体相对速度门限 `grasp_max_relative_speed`；`tilt_angle_max_deg` 是另一个控制器/飞行节点参数，不和最大速度一一对应。应同时检查轨迹参考及 EKF 实测速度。

例如，`2026-10-30-00-41-11.bag` 的参数快照中 `vmax=0.40 m/s`，三次接近至抬升计时结束的 EKF 三维速度峰值约为 0.662、0.726、0.664 m/s；接近阶段的控制器速度参考峰值也超过 0.4 m/s。这是该次记录的现象，不代表之后每次运行都会出现同样的峰值，也不能从中单独归因于某一个参数。

### 5. 数据有效性与运行参数

`target_timeout`、`target_twist_timeout`、`odom_timeout` 和 `flight_status_timeout` 默认均为 0.20 s；小车位姿与速度接收时间差上限 `target_pose_twist_max_skew` 默认为 0.15 s。它们是数据有效性条件；如果频繁超时，先检查实际话题频率、延迟和丢包，再决定是否调整。速度 header 的时钟偏移及无法识别固定传输延迟的限制见“数据新鲜度与异常退出”。

启动后可在实际运行的机器上核对参数：

```bash
rosparam get /drone0/planning/vmax
rosparam get /drone0/planning/amax
rosparam get /drone0/planning/target_velocity_cutoff_hz
rosparam get /drone0/planning/grasp_yaw_velocity_filter_hz
rosparam get /drone0/planning/grasp_start_dis
rosparam get /drone0/planning/grasp_max_relative_speed
rosparam get /drone0/planning/grasp_position
rosparam get /drone0/planning/grasp_lift_abort_distance
rosparam get /flygripper/servo_node/teleop_mode
```

舵机节点需要 `teleop_mode=2` 才会消费规划器的位置命令。规划器启动时读取参数；修改 `planning.launch` 后需将代码和启动文件同步到实际运行的板端并重启规划器。运行中修改参数服务器上的值不会更新节点已读取的值，`rosparam get` 或新快照显示的值也不一定是节点缓存值。

### 按现象定位，不要先同时调整多个参数

| 现象 | 先检查的证据 | 相关参数 / 下一步 |
|---|---|---|
| 触发后没有接近 | `/triger`、目标与 EKF 新鲜度、`/flygripper/flight_trajectory_status`、规划日志；区分生成轨迹和飞行节点采样 | 输入话题、超时、`vmax`；先确认本次轨迹和飞行状态，不先放宽闭爪门限。 |
| 到附近一直不闭爪 | `grasp_phase`、实际位置和目标参考、相对速度、yaw 与飞行状态；判断单项是否连续达标 | `grasp_start_dis`、`grasp_max_relative_speed`、航向速度滤波和就绪判断、`grasp_gate_duration`。当前 bag 没有逐项门限和计时状态话题，离线重算不能完全复现板端回调。 |
| 已有闭爪命令但看不到动作 | `/flygripper/actuator_command`，再检查舵机模式、串口写入/ACK、新鲜反馈与现场动作 | `grasp_position`、`teleop_mode`、通信和机构；不要仅凭 `graspState=1` 判断舵机已闭合。 |
| 抬升前或抬升中异常中止 | `grasp_phase`、规划器 `/rosout` 原因、飞行轨迹状态、目标/里程计新鲜度、位置和速度误差 | 先按日志确认超时、轨迹不可行或跟踪误差，再查 `grasp_abort_*`、`grasp_lift_abort_distance`。闭爪计时到期不证明抓住物体。 |
| 运动时方向抖动或转向跟不上 | 原始及滤波后目标速度、目标/实际 yaw、yaw 角速度、位置参考和 EKF | 先区分目标速度噪声与飞机控制响应；再单独评估 `target_velocity_cutoff_hz`、`grasp_yaw_velocity_filter_hz`、yaw 限速。滤波会延迟真实转向，不能以静止实验替代动态验证。 |

每项参数的完整说明和适用阶段见 [参数参考](PARAMETERS.md)。

测试时建议记录小车 `/vrpn_client_node/HIARM_car/pose` 和 `/vrpn_client_node/HIARM_car/twist`、无人机 `/ekf/ekf_odom`、`/flygripper/trajectory`、`/flygripper/flight_trajectory_status`、`/flygripper/actuator_command` 和 `/drone0/planning/grasp_phase`，并结合实际动作观察判断。飞行节点状态与夹爪命令分别只能说明本地控制输出和命令发布，不能证明飞控收到指令、舵机动作或物体被抓住。

默认的 `bags/bag.sh` 也订阅上述状态话题、`/graspState`、`/drone0/replanState` 和触发话题；实际 bag 只包含录制期间有发布的消息。收到着陆触发并到达着陆目标后，规划器持续刷新已登记的悬停轨迹；目标偏离到位条件时可重新规划，飞行状态失效仍会触发异常制动。

着陆到位时，悬停航向取切换时刻正在执行的航向参考，后续刷新保留航向多项式，使 yaw 和 yaw 角速度连续，并在既有角速度、角加速度限制内收敛到保持状态，不回到任务触发时的航向。

这里的“着陆”分支只规划到小车刚体系下的 `pos_dx/pos_dy/pos_dz + land_p` 目标点并悬停。默认 `scripts/land_triger.sh` 的 `land_p` 为零，因此仍保留默认 0.09 m 抓取高度偏移。它没有自动下降至接触、确认接地、切换飞控 LAND 模式或上锁的完整流程。`scripts/sitl/test_auto_takeoff.py` 中另有通过飞控 LAND 模式降落的仿真测试；飞行节点的异常接管模式可配置为 LAND，但当前 `handover_mode` 默认是 ALT_HOLD，这与规划器的着陆到位悬停是不同路径。

每次 `/triger` 都开始新的抓取任务，并清除此前的着陆触发和偏移。若新任务需要进入着陆分支，应在该次 `/triger` 之后再发送 `/land_triger`。

## 抓取状态

`/drone0/planning/grasp_phase` 是带锁存的 `std_msgs/String`，可能的值包括 `approach`、`opening_assumed`、`closing_assumed`、`lifting_assumed`、`braking`、`hold_assumed` 和 `aborted`。后缀 `assumed` 表示根据计时作出的假设，不表示物理抓取已经确认。

`/graspState` 保留为可视化输出，规划器不再订阅该话题。发布闭爪命令前，`graspState` 和 `graspDegree` 为 0；一旦发出闭爪命令，包括之后异常退出时，这两个值均为 1。消息会填写 header 和重新规划时间。请用 `grasp_phase` 观察任务进度，不要将这两个字段当作夹爪反馈或外部控制接口。

## 本地验证

在 ROS One ARM64 构建环境中，从工作区根目录执行：

```bash
source /opt/ros/one/setup.bash
catkin build flygripper_msgs flygripper_flight planning --no-status -j2 -p1 --cmake-args -DCATKIN_ENABLE_TESTING=ON
source devel/setup.bash
ctest --test-dir build_catkin/planning -R moving_grasp --output-on-failure
python3 src/planning/planning/test/test_moving_grasp_ros.py
```

C++ 测试检查计时、门限持续计时重置、过期数据拒绝、位置/速度/加速度端点、抬升连续性、速度滞回、角度跨界、转弯预测、航向限制、低速方向噪声和稳定运动持续判断；平移滤波还检查 Hz 系数、截止频率衰减、首帧与断流恢复、关闭滤波及无效输入。

Python 测试在本机端口 11371 启动独立 ROS master 和实际规划器，并输入合成动捕数据及运动学无人机状态。它检查直线和转弯跟随、0.7 米距离接近、闭爪计时、抬升与减速、位置/速度/加速度及 yaw 连续性、闭爪门限、数据丢失、跟踪误差退出和重新触发；还检查独立 twist 输入、twist header 时钟不同步、静止噪声、twist 缺失或超时，以及时间戳重复。测试模拟飞行状态消息，不启动真实飞行、MAVROS 或舵机节点，也不模拟真实飞行动力学、物体接触或夹持保持。
